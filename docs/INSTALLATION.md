# Installation Guide

FacilityFlow runs in two modes. Start with **Static Mode** (no server needed) and
enable **Backend Mode** later if you need multi-user accounts — no reinstall required.

## Requirements

- Node.js 18+ (Node 22 recommended) and npm — only for building / backend
- Any static web host for Static Mode
- Docker (optional, for one-command full-stack)

---

## Option 1 — Static Mode (fastest, no backend)

```bash
npm install
npm run dev          # develop at http://localhost:5173
npm run build        # production build in dist/
```

Upload the contents of `dist/` to any static host (Netlify, Vercel, Cloudflare
Pages, GitHub Pages, IIS, Apache, nginx). SPA fallback configs are included:

| Host | File (already in the package) |
|---|---|
| Netlify | `_redirects` (auto-copied into dist) |
| Vercel | `vercel.json` |
| Apache | `.htaccess` (auto-copied into dist) |
| IIS | `web.config` (auto-copied into dist) |
| nginx | `deploy/nginx.conf` |
| GitHub Pages | `404.html` (generated by the build) |

Admin panel: `https://your-site/admin` — default password **facility2026**.
Change it by setting `VITE_ADMIN_PASSWORD_HASH` (bcrypt hash) or
`VITE_ADMIN_PASSWORD` (plain) in a `.env` file before building.

For SEO, build with your real domain: `SITE_URL=https://map.company.com npm run build`
(this bakes the correct URLs into `sitemap.xml`).

---

## Option 2 — Backend Mode (multi-user)

### A. Docker Compose (recommended)

```bash
docker compose up --build
```

- Frontend: http://localhost:8080
- API: http://localhost:4000 (health: `/api/health`)
- SQLite data persists in the `facilityflow-data` volume.

⚠️ Edit `docker-compose.yml` first: change `JWT_ACCESS_SECRET`,
`JWT_REFRESH_SECRET` and `SEED_ADMIN_PASSWORD`.

### B. npm scripts (local development)

```bash
npm install && npm --prefix server install
cp server/.env.example server/.env      # edit secrets!
npm run start:full                      # frontend + backend together
# or separately:
npm run dev                             # frontend only
npm run start:backend                   # backend only
```

### C. Production (PM2 + nginx)

```bash
npm run build && npm run build:backend
pm2 start ecosystem.config.cjs          # keeps the API alive
# serve dist/ with nginx using deploy/nginx.conf
```

### First login (Backend Mode)

The database is seeded on first start:

| Account | Password | Role |
|---|---|---|
| admin@facilityflow.local | ChangeMe123! | Super Admin |
| manager@facilityflow.local | Manager123! | Facility Manager |
| editor@facilityflow.local | Editor123! | Editor |
| viewer@facilityflow.local | Viewer123! | Viewer |

**Change or delete the demo accounts immediately in production.**

### Turning Backend Mode on

1. Open `/admin` → **Settings** → **Backend Mode (Pro)**.
2. Enter your API base URL (e.g. `https://api.company.com`) and click
   **Test connection**.
3. Tick **Enable Backend Mode** — the app reloads and now reads/writes through
   the API. Sign in with a backend account.

If the API ever goes down, the public map automatically falls back to the last
static `data/map-data.json` and shows a small warning badge.
